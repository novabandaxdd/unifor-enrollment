Por que separar IAM do Backend? O Keycloak centraliza autenticação — o Quarkus não armazena senhas, apenas valida o JWT via OIDC discovery endpoint. Isso isola a camada de segurança e permite trocar o Identity Provider no futuro sem alterar nenhuma linha do código de negócio.

UNIQUE(aluno_id, aula_matriz_id) + soft-delete + upsert A constraint de banco impede duplicatas absolutas. O campo ativo=false preserva histórico acadêmico sem deletar registros. O MatriculaService usa o padrão upsert: se já existe uma matrícula cancelada para o mesmo par aluno/aula, ela é reativada em vez de inserir uma nova linha — eliminando ConstraintViolationException sem abrir mão da integridade referencial.

Por que PESSIMISTIC_WRITE elimina race condition? O em.find(AulaMatriz::class.java, id, LockModeType.PESSIMISTIC_WRITE) emite um SELECT FOR UPDATE que bloqueia a linha no PostgreSQL. Se dois alunos clicam simultaneamente, o segundo fica em espera no banco — não chega nem às validações — até o primeiro commitar. Resultado: impossível dois alunos ocuparem a mesma última vaga.

Armadilha resolvida — keycloak-angular v20 A v20 deprecou KeycloakService. O correto é inject(Keycloak) direto do pacote keycloak-js.
